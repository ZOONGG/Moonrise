## What prevents direct loading

`MainWindow.xaml.cs` applies maintained-build resolution first, then `WeaveModApiInspector` detects API namespaces and rejects `HasLegacy && HasCurrent` before launch. Original BWH SHA `c39f…` still resolves to the existing maintained `6da5…` runtime. Java agents, including FastPlace, do not participate in this classification.

Raven declares lowercase `entrypoints` and legacy `about`, but lacks required current `name`, `modId`, and `namespace`. Current uses `entryPoints`. Its entrypoint implements `net.weavemc.loader.api.ModInitializer.preInit()`, while current casts to `net.weavemc.api.ModInitializer` and invokes `preInit(Instrumentation)`. Removing the guard would not solve metadata, missing classes or the interface cast.

Raven preInit registers GUICommand and itself on the legacy bus. `Raven.init()` is reached later by `StartGameEvent.Post`, not by the new current `init()` lifecycle method. The current loader creates entrypoint instances separately for preInit and init: a facade must ensure registration remains once-only and current init remains a no-op for this legacy contract.

The class audit found legacy Command/CommandBus, SubscribeEvent/EventBus, Event/CancellableEvent, Keyboard, Mouse, ChatReceived, RenderGameOverlay (Pre/Post), RenderHand, RenderLiving (Pre/Post), RenderWorld, Shutdown, StartGame (Post), Tick, and World event types. Raven also defines its own events, posts them from its own Mixins, and uses subscribe/unsubscribe on module objects. Renaming packages alone would not preserve those contracts.

Current `callEvent` is `postEvent`; SubscribeEvent has a different class identity. Current commands use `execute`, varargs `register`, and include the command name in arguments; legacy `handle` receives arguments after the name and legacy bus executes all matching commands. ChatReceived/ChatSent became ChatEvent.Received/Sent; ServerConnect became ClientConnectedToServer. Binary and semantic mapping must be explicit.

## Required shared pipeline

1. **Metadata:** synthesize current ModConfig in memory at discovery and registration, preserving original entrypoint/config declarations. Detect the legacy schema, validate class names and unique IDs, and use an explicit `mcp-named`/1.8.9 profile backed by Raven's named references. Do not rewrite weave.mod.json or create a Raven-specific replacement archive. Adapt every metadata consumption point, including early discovery/remapping.
2. **ABI:** define legacy interface/event/command facades once in the game loader. The legacy ModInitializer facade can extend the current interface and delegate preInit(Instrumentation) to preInit(). Preserve legacy custom Event subclasses and cancellation. Unknown API members must fail preflight.
3. **Events:** route current Minecraft API events to legacy listeners with preserved mutable values, cancellation, order and object unsubscribe identity. Preserve old command behavior without changing BWH's current command dispatch. Avoid duplicate subscriptions, recursive translations and double delivery to wildcard current Event listeners.
4. **Mixin:** register Raven's original 11 Mixins and maintained BWH's config in the existing current `mcp-named` sandbox before target selection. Supply matching facade class bytes through the sandbox byte provider as well as game definitions; facade visibility only on the system classpath is insufficient. Preserve current Mixin relocation and the existing synthetic technical agent.
5. **Mappings/classloading:** reuse current Minecraft mappings and executable remapping for game definitions and sandbox byte lookup. Raven uses named targets such as Minecraft.runTick and Minecraft.getMinecraft; declaring a namespace does not prove target resolution against Lunar. Match class identity across game, loader helpers and sandbox, including callback descriptors and Kotlin relocation. Do not append the complete legacy loader to the game classpath.
6. **Dependencies:** keep current core and `net.weavemc.api:api-v1_8:1.3.4` resolved by the existing current loader. Core alone lacks Minecraft event/command classes. Raven also references Minecraft 1.8.9, LWJGL2, Guava, Gson, Authlib, Netty, Commons Lang3 and Apache HttpClient. These references require game-classpath visibility; declarations do not prove availability. Legacy Kotlin API references need matching runtime or current shaded relocation. Mixin annotations/callbacks use current sandbox relocation. No new dependency download is performed by this proof.

## Bridge versus two runtimes

| Approach | Assessment |
| --- | --- |
| One current runtime + legacy facade | Reuses BWH pipeline, one mapping/target transformation owner, and a common compatibility contract. Requires metadata interception, explicit event semantics, game/sandbox visibility and compatibility checks. Preferred. |
| Both complete runtimes | Legacy has its own Mixin service, transformer, HookManager, lifecycle hooks and bus; current has its own shaded Mixin sandboxes, modifiers, mappings and Minecraft API hooks. Shading avoids some package collisions but does not coordinate transformations of the same Minecraft classes. Separate classloaders do not isolate game state or unify event delivery. Ordering, duplicate hooks and cancellation would require an additional coordinator. No dual-runtime compatibility proof exists here. |

A shared facade is technically feasible for a bounded legacy API profile. It can support other untouched legacy mods using that profile without separate patched JARs. It is not universal certification of all 0.2.x mods: direct loader internals, Hook/AssemblerConfig differences, ASM assumptions, Kotlin ABI, unusual namespaces, reflection and Mixin plugins need separate contract coverage or rejection. Version/hash binding and runtime dependency verification remain necessary.

## Original Raven changeYaw selector diagnosis — 2026-10-09

**Root cause: the original Raven injector requests the fifth live float at method HEAD, where only two floats exist.** The enclosing method selector resolves correctly. This is an original Raven selector defect/inactive injection on this bytecode, not an offline dependency, mappings or relocation error. No adapter correction is justified.

The untouched Raven archive (SHA-256 `c6edd2979121df4f7c2585abee8da0b84e3b7b5496b0b1a4a684edad179727a1`) contains:

```java
@Mixin(RendererLivingEntity.class)
@ModifyVariable(
    method = "doRender(Lnet/minecraft/entity/EntityLivingBase;DDDFF)V",
    at = @At("HEAD"), ordinal = 4)
public float changeYaw(float input) {
    System.out.println(input);
    return input + 90;
}
```

The Mixin annotation applies to the class; the ModifyVariable annotation applies to the handler. The handler is public, non-static, descriptor `(F)F`. Its instructions are `GETSTATIC System.out`, `FLOAD 1`, `INVOKEVIRTUAL PrintStream.println(F)V`, `FLOAD 1`, `LDC 90.0f`, `FADD`, `FRETURN`. No module setting, event or Raven initialization is referenced by this body. An ASM scan of every original archive class finds zero direct references to this handler.

The original annotation has no `@At.target`, invocation owner/name/descriptor, opcode filter, shift, slice restriction, index, variable-name restriction, `argsOnly`, explicit `require`, `expect`, `allow` or constraints. Relevant Mixin defaults are: shift NONE, whole-method slice, argsOnly false, index -1, names empty, remap true, require -1 (inherit configuration), expect 1 (debug count validation). `ordinal=4` belongs to **ModifyVariable's local discriminator**, not At's instruction ordinal and not JVM local slot 4. The return type `F` determines the local type. HEAD selects the first instruction-list node (a label in this input), before the first executable instruction; it does not search later float loads/stores or method calls.

Exact target owner: `net/minecraft/client/renderer/entity/RendererLivingEntity`; name: `doRender`; descriptor: `(Lnet/minecraft/entity/EntityLivingBase;DDDFF)V`. Its bridge overload with `Entity` is excluded by that explicit descriptor.
